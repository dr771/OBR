## Risks / Trade-offs
Review figures are a manually supplied snapshot, not an API integration. Real logo files vary in intrinsic color (Holster's cool gray, Pas de Monaco's olive) and file format (raster PNG plus SVG using `currentColor`, which resolves to black when loaded via `<img>` rather than inheriting page CSS) - normalized with a shared grayscale-at-rest/full-color-on-hover treatment (`.ob-brand-logo` in both `component-ob-home-marquee.css` and `component-ob-merken.css`) rather than per-brand color overrides, so the row/grid reads as one system. `assets/ob-logo-nike-swim.*` is PNG-format bytes served from a `.jpg`-named source URL; renamed to `.png` before adding to the theme. `assets/ob-logo-irasuto-studios.png` shipped from its source with an opaque white background baked in (no alpha channel) rather than transparency; harmless on a pure-white page but would show as a visible box once the marquee got its own tint, so it was re-matted to a proper black-on-transparent PNG (luminance-as-alpha) before the tinted band shipped. RH+'s only available source file (from its own site's navbar) is white text + red bars on transparent, built for a dark surface with no dark-on-light variant published - rather than source a third-party vector of uncertain accuracy, it ships as-is with a permanent CSS invert (`.ob-brand-logo--invert`) instead of the usual grayscale/color-on-hover pair, since there is no legible brand-color state to reveal for this one. RH+'s Shopify collection isn't synced yet (see COLLECTIONS.md), so its marquee block uses a new `brand_handle` text setting instead of the `collection` picker and links to `/collections/rh-plus`, which 404s until Akeneo syncs it - accepted per owner instruction rather than pre-creating an empty placeholder collection.

A second owner review flagged the marquee's tint as clashing with the hero's outlet badge directly above it (two different light-blue-ish colors reading as a seam) and several logos (Holster, Pas de Monaco, Sneaker Lab's text) as still too pale even at 90% opacity. Fixed by: sharing one color between the two (`#edf7fd`, moved from the badge to the marquee; the badge got a new bold solid-accent hover so it isn't left with no distinct hover state of its own); and stacking `brightness(0.5) contrast(1.15)` after `grayscale(1)` on `.ob-brand-logo` so lighter source files get pulled down toward the near-black logos' apparent weight instead of keeping their own (lighter) original luminance - plain grayscale preserves lightness, which was exactly the problem. Löwenweiss also got a real logo (owner-supplied URL) at this point, leaving Sneaker Lab the only text fallback.

The same review asked that hovering the marquee slow it down rather than stop it outright. A CSS animation can only toggle `animation-play-state` instantly, and changing `animation-duration` while a `%`-based keyframe is running doesn't ease either - the browser recomputes position against the new duration at the same elapsed time, producing a visible jump. `assets/ob-home-marquee.js` replaces the keyframe with a `requestAnimationFrame` loop that eases a px/sec speed value toward a slower target on hover/focus (and back on leave), writing `transform` directly - verified via sampled position deltas that the deceleration/reacceleration is smooth with no jump or stop-to-zero.

A third review compared this section's responsive behavior directly against the reference proto (two screenshots at different widths) and asked for a match. Inspecting bolt.host's actual Tailwind classes (not guessing from screenshots) found its floating cards are `hidden md:block` (768px) while its two-column switch is a separate, later `lg:grid-cols-2` (1024px) - two breakpoints, not our one shared 990px. It also has no CSS `order` reshuffling at all: copy comes before photo in plain DOM order at every width, including fully stacked mobile, whereas this section had shipped with `order: 1`/`order: 2` deliberately putting the photo first on narrow/stacked widths. Matched exactly: floating cards now gate on 750px (this theme's own already-used tablet breakpoint, close enough to bolt's 768 to reuse rather than add a third breakpoint value), the two-column switch moved from 990px to 1024px as its own media query, and the `order` properties were removed so copy always leads. A follow-up screenshot caught one more gap the breakpoint fix alone didn't close: `.ob-home-hero__media` had a `max-width: 44rem; margin: 0 auto` capping the photo to a narrow centered block on tablet, while bolt's photo (a plain `grid-cols-1` track, same as the copy above it) runs the full column width at every stacked size. Removed the cap entirely rather than gating it to a range - there was no longer a "keep it small on true mobile" reason for it once the two-column breakpoint moved to 1024px.

A fourth review, after seeing the full-width tablet photo live, asked for three more fixes: the now-full-width square photo stood too tall on tablet; the outlet badge's owner-dictated `left: -6rem` (tuned for the narrow ~42% desktop column) pushed it out past the photo's own left edge now that the photo runs edge-to-edge; and mobile should show both floating cards after all (a deliberate departure from the proto, which hides them below 768px) with their sizing adjusted to fit. Fixed together: the photo gets a 3:2 ratio between 750-1023px (back to square at 1024px, where the narrower side column doesn't need it); both floating cards now render at every width, `display: none` removed entirely; and the cards get their own compact size and inset position (small positive `top`/`right`/`bottom`/`left` offsets, ~85% of desktop's icon/text/arrow sizing) as the base/mobile+tablet rule, with the full desktop size and the owner's overflow position restored inside the 1024px query.

Between the second and third reviews the owner also repositioned the outlet badge directly (exact `bottom`/`left`/`background` values supplied, not derived from the proto) - `bottom: -1.6rem` → `5.4rem`, `left: -1rem` → `-6rem`, `background: #edf7fd` → `#ffffff`. Applied as given; the badge's bold-accent hover (added for the marquee-color-clash fix above) still applies on top of the white rest state unchanged.
